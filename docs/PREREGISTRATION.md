# 事前登録：地盤susceptibility項の追加（2026-07-26）

本書は、Triage優先度ヒューリスティックへ「道路長と独立な地盤susceptibility項」を
追加する変更について、**測定を行う前に**設計を固定するための文書である。

事前登録する理由は一つしかない。`baseline_road_length_spearman_rho`（現行 ρ=0.903）を
下げることは、重み・写像・欠測処理をいじれば容易に達成できてしまうからである。
「ρ が下がった」という結果に意味を持たせるには、**その結果を見る前に設計を確定し、
確定した事実を検証可能な形で残す**必要がある。本書のコミットが、その記録である。

本書はコミット後に**内容を変更しない**。実測値は本書には書かず、別途
`golden_snapshot_expected_metrics.json`（単一情報源）と `docs/SPEC.md` §9.3 に記録する。

---

## 1. 検証する問い

**公開衛星データ由来の優先度ランキングに、道路長と独立な地盤情報を1つ足すと、
「実質ただの道路長の地図」という現状（ρ=0.903）から抜け出せるか。**

これは予測精度の問いではない。`docs/SPEC.md` §7.3 の片側 p=0.9616（中核仮説が
支持されなかったこと）は本変更では一切解決しない。**独立性と妥当性は別の問題**である
（§6 で解釈の事前宣言を行う）。

## 3. 空間結合の方式（測定前に確定）

**メッシュ重心での代表値抽出を採る。**

本プロジェクトの250mメッシュは平面直角座標系IX系（EPSG:6677）上の等面積グリッド
（`backend/core/mesh.py`）であり、J-SHIS は緯度経度ベースのJIS地域メッシュである。
解像度は同じ250mだが格子の切り方が異なるため、**メッシュコードによる結合はできない**
（実測：本AOIの7,918メッシュとJ-SHIS側コードの一致は0件）。

したがって各MeshCellの重心が含まれるJ-SHISメッシュの値を採る。これは既存の土地利用
取込（`backend/ingest/kokudo_suuchi.py`）と同じ作法である。

**限界（先に明記する）**：面積按分ではないため、境界セルでは最大1セル分ずれうる。
250m対250mでほぼ同サイズなので影響は限定的と考えるが、面積最頻値を採る方が
境界付近では妥当である。実装の単純さと既存作法との一貫性を優先した判断であり、
この選択自体は ρ の結果を見て決めたものではない。

## 4. susceptibility の定義（測定前に確定）

```
ground_susceptibility = _normalize( -AVS30 )
```

AVS30 が低いほど軟弱地盤であり、値が大きくなるよう符号を反転して既存の `_normalize`
（min-max）に通す。**手で割り当てる数値は一つもない。**

### 微地形区分（JCODE）を入力に使わない理由

ロードマップの当初案は「微地形区分＋AVS30 の2信号」だった。しかし微地形区分は24分類の
カテゴリ値であり、susceptibility へ写像するには**24個のスコアを人手で決める**ことになる。
それは事前登録が排除しようとしている調整余地そのものであり、「ρ が下がるように選んだ
のではないか」という疑いを原理的に否定できない。

よって**入力には連続実測値である AVS30 のみを使う**。微地形区分は `GroundClass.
ground_classification` に格納し、**検証に用いる**（§5）。

### 欠測の扱い

AOI外・データ欠損・`JCODE=0`（未分類）のメッシュは、**AOI内 AVS30 の中央値**で補完する。
0で補完すると「最も硬い地盤」を意味してしまい偏るため。

## 5. 重み（測定前に確定）

| 項 | 現行 | 変更後 |
|---|---|---|
| `subsidence_signal` | 0.4 | **0.2** |
| `ground_susceptibility` | — | **0.2** |
| `road_exposure` | 0.3 | **0.3**（変更なし） |
| `past_events` | 0.3 | **0.3**（変更なし） |

**根拠**：現行の 0.4 は「地盤の状態」を表す枠である。そこへ同格の地盤条件シグナルが
1つ増えたので、**その枠を等分する**。沈下速度と地盤軟弱度はいずれも検証済みの予測子では
なく（`METHOD_VALIDATED=False`）、epistemic な地位が等しいため優劣をつける根拠がない。

この置き方の重要な性質は、**`road_exposure` と `past_events` に一切触れないこと**である。
「ρ を下げるために道路長の重みを削る」という操作が構造的に起こり得ない。

## 6. 測定する量と、結果の解釈（測定前に宣言）

### 測定する量

1. `baseline_road_length_spearman_rho`（変更後）— 比較対象は現行の **0.903368503464283**
2. `ground_susceptibility` **単独**と `road_length_m` の Spearman 順位相関
   — 追加したシグナル自体が道路長と独立かどうかの直接確認
3. 微地形区分ごとの `ground_susceptibility` 平均 — **検証用**。埋立地・旧河道・後背湿地が
   上位に、台地・山地が下位に並べば、この指標が土木的機序と整合していることを読み手が
   確認できる。並ばなければ指標が疑わしいという情報になる

### 解釈の事前宣言

**ρ が下がった場合**：独立性は改善したと言える。ただし**予測性能の主張には一切ならない**。
中核仮説の非支持（片側 p=0.9616）は本変更で何も変わらず、`METHOD_VALIDATED` は
`False` のままである。「道路長の言い換えではなくなった」ことと「当たる」ことは別問題。

**ρ が下がらない／上がった場合**：より強い否定的結論になる。すなわち
**「公開データの範囲では、衛星由来の沈下情報に地盤情報を足しても、道路長の代理から
抜け出せない」**。この場合も結果をそのまま公開する。

いずれの場合も、`docs/SPEC.md` §9.3 と `golden_snapshot_expected_metrics.json` を
実測値で更新し、README の商用化ロードマップ該当行に結果を反映する。

## 7. 本変更で**変わらない**もの

- 片側 p=0.9616（パーミュテーション検定）
- Moran's I = 0.797
- `METHOD_VALIDATED = False`
- 連続スコアをAPIへ出さない制約（tier化は維持）
