# 事前登録と、その撤回：地盤susceptibility項の追加（2026-07-26）

## 結論

**測定を実施せず、撤回した。**

商用化ロードマップの「次の一手」として挙げていた「道路長と独立な地盤susceptibility特徴量を
1つ追加し、事前登録した重みで ρ を再測定する」という施策について、設計を事前登録した直後に
独立監査を行った。その結果、**この検証設計には情報量がないことが判明した**ため、測定を
行わずに撤回する。

本書はその経緯の記録である。撤回した事実と理由を残すことが、実施しなかったことより重要だと
判断した。以下では §1 に登録した内容を**原文のまま**残し（誤りを含む。§3 で訂正）、
§2〜§4 に監査結果と撤回理由を記す。

---

# §1 撤回前に登録した内容（原文・誤りを含む）

> **注意**：以下は 2026-07-26 に登録した原文である。§3 で述べる事実誤りを含むが、
> 記録としての価値を優先し、書き換えずに残す。

## 1-1. 検証する問い

公開衛星データ由来の優先度ランキングに、道路長と独立な地盤情報を1つ足すと、
「実質ただの道路長の地図」という現状（ρ=0.903）から抜け出せるか。

## 1-2. 使用するデータ

J-SHIS（防災科学技術研究所）表層地盤データ V4（2020年版）。
`Z-V4-JAPAN-AMP-VS400_M250-5339.zip`（1次メッシュ5339＝東京。約851KB）。
列 `CODE, JCODE, AVS, ARV`（V4実データは `AVS_EB, AVS_REF` を追加で持つ）。
`AVS`（表層30mの平均S波速度 m/s）を入力に、`JCODE`（微地形区分24分類）を検証に使う。

## 1-3. 空間結合

メッシュ重心での代表値抽出。各MeshCellの重心が含まれるJ-SHISメッシュの値を採る。
（原文：「これは既存の土地利用取込（`backend/ingest/kokudo_suuchi.py`）と同じ作法である」）

## 1-4. susceptibility の定義

```
ground_susceptibility = _normalize( -AVS30 )
```

（原文：「入力には連続実測値である AVS30 のみを使う」「手で割り当てる数値は一つもない」）

微地形区分（JCODE）を入力に使わない理由は、24分類のカテゴリ値を susceptibility へ写像するには
24個のスコアを人手で決めることになり、それが事前登録の排除しようとしている調整余地そのものだから。
欠測（AOI外・`JCODE=0`）は AOI内 AVS30 の中央値で補完する。

## 1-5. 重み

| 項 | 現行 | 変更後 |
|---|---|---|
| `subsidence_signal` | 0.4 | 0.2 |
| `ground_susceptibility` | — | 0.2 |
| `road_exposure` | 0.3 | 0.3（変更なし） |
| `past_events` | 0.3 | 0.3（変更なし） |

根拠は「現行の 0.4 は『地盤の状態』の枠であり、同格の信号が増えたのでその枠を等分する」。
この置き方だと `road_exposure` と `past_events` に一切触れないため、
「ρ を下げるために道路長の重みを削る」操作が構造的に起こり得ない、と主張した。

# §2 独立監査が見つけたこと

事前登録の直後、3つの独立した監査（方法論／地盤工学／敵対的レッドチーム）を実施した。
3者は**独立に同じ致命的欠陥へ収束した**。

## 2-1. 【致命的】この検証設計には情報量がない

道路長と無相関な項を重み 0.2 で足せば、**中身が何であれ ρ は下がる**。
レッドチームが golden snapshot 上で実測した値：

| 第4項の中身 | ρ |
|---|---|
| なし（現行） | 0.903 |
| AVS30（本命） | 0.852 |
| **純粋な一様乱数** | **0.531** |

**乱数の方が「良い」スコアを出す。** したがって「ρ が下がった」という観測は、
「道路長と独立な地盤情報を足せた」ことの証拠にならない。「独立な**何か**を足した」ことの
証拠にしかならず、情報とノイズを区別しない。

さらに悪いことに、**空間結合のバグ・CRS の取り違え・欠測の取りこぼしが、すべて
「望ましい結果」として報われる**。測っている量が、検証したい仮説と逆向きの誘因を持つ。

## 2-2. ρ=0.903 の真因は重み配分ではなく正規化関数だった

同じ監査が、各項の実効的な効きを実測した。

| 項 | 名目重み | `_normalize` 後の中央値 | 実効的な効き |
|---|---|---|---|
| `subsidence_signal` | 0.4 | **0.045**（最大1点が1.80、p95は0.174） | ほぼゼロ |
| `road_exposure` | 0.3 | 約0.5（sd 0.14） | **支配的** |
| `past_events` | 0.3 | 0（**非ゼロは7,082中25セル＝0.35%**） | ほぼゼロ |

min-max 正規化と極端に歪んだ入力の組み合わせが、**名目重み 0.4 の項を実効 0.02 に潰している**。
ρ=0.903 は「重み配分の結果」ではなく「正規化関数の選択の結果」である。

これは §1-5 の重み設計が、そもそも問題の所在を取り違えていたことを意味する。

## 2-3. 事前登録が縛れていた自由度はごく一部だった

レッドチームは、**登録文言を1文字も破らずに ρ を 0.903 → 0.38 まで落とせる**経路を実証した。
素直な実装の 0.852 との差のほぼ全部が、後付けの正当な理由を伴って達成可能だった。

最も重大なのは、**`baseline_road_length_spearman_rho` の算出式を登録し忘れていた**こと。
比較対象の数値（0.903368503464283）だけ指定し、その作り方を定義していなかった。
tier 化後の値を使う、両側を tier 化する等はいずれも文言違反ゼロで、しかも
「APIが公開するのは tier なのだから tier で測るのが正しい」という**より誠実に聞こえる**
論法まで使えた。

他に縛れていなかったもの：`_normalize` の実装そのもの、他3項の前処理、
`eligible_pool` の定義、tier の分位数、AVS30 の格納型、測定の反復回数。

## 2-4. 判定閾値と撤回規則がなく、反証不能だった

「ρ が下がれば独立性改善、下がらなければより強い否定的結論」という §1 の宣言は、
**どちらに転んでも成果として語れる**構造だった。低下がどれだけあれば「抜け出せた」と
言うのかの数値基準がなく、ρ が下がらなかった場合に第4項を外すのかどうかも書かれていなかった。
反証されるものが何もない事前登録は、事前登録ではない。

# §3 §1 に含まれていた事実誤り（2件・自分で検証した）

## 3-1. 「AVS30 は連続実測値」は誤り

J-SHIS の AVS30 はメッシュごとの実測値ではなく、**モデル推定値**である。
本書 §1-2 が引用する出典の表題自体がそれを示している ——
松岡・若松(2008)「**地形・地盤分類250mメッシュマップ全国版に基づく**地盤のゆれやすさデータ」。

つまり「24分類に人手でスコアを割り当てる」作業は消えたのではなく、**他人が・別の目的
（地震動増幅）のために・別の応答変数に合わせて推定した係数へ外注された**だけである。
その係数はリポジトリ内から見えず、監査も差分も取れない。事前登録の透明性という観点では、
明示した24個のスコアベクトルより**劣る**。

**副次的な帰結が2つある。**

第一に、§1-4 が「検証」と位置づけた微地形区分による確認（埋立地・旧河道が上位に並ぶか）は、
AVS が JCODE の関数である限り**ほぼトートロジー**であり、独立な妥当性証拠にならない。

第二に、関東以外の推定式は**標高を説明変数に含む**。本プロジェクトは `docs/SPEC.md` §5.1 で
「本AOIの低標高は過去の地盤沈下の累積結果であり、標高を沈下の説明変数に使うのは循環」として
これを明示的に禁じている。**自ら禁じた変数を裏口から導入する**恐れがあった。

実データを確認したところ、1次メッシュ5339 の `AVS_REF`（AVS30 の出典分類）は
**`0` が 4,911件・`1` が 88,563件と2方式が混在**していた。§1 はこの存在に触れていない。

## 3-2. 「既存の土地利用取込と同じ作法である」は誤り

`backend/ingest/kokudo_suuchi.py` を読み直した結果、実装は**逆向き**だった。

```python
centroid_projected = land_use.geometry.to_crs(PROJECTED_SRID).centroid  # ソース側の重心
joined = gpd.sjoin(centroids, mesh_cells, predicate="within")           # メッシュに含まれるものを集める
majority = joined.groupby("mesh_cell_id")["land_use_class"].agg(...)    # 最頻値
```

「ソース側ポリゴンの重心をメッシュへ落として最頻値」であり、§1-3 が書いた
「MeshCellの重心が入るソースメッシュの値を採る」とは別物である。この一文があると、
実装者が2通りの互換な実装を選べてしまう。

# §4 地盤工学の観点：AVS30 は陥没リスクの代理として機序に反する

方法論とは独立に、指標選択そのものにも問題があった。

陥没の機序は「管の欠損 → 周辺土砂が**吸い出される**（内部侵食）→ 空洞が上方進展 →
交通荷重で路面崩落」であり、律速要因は**粒度組成・細粒分含有率・透水性**であって
剛性ではない。AVS30 は微小ひずみ剛性の指標にすぎない。

**この AOI では符号が逆転する。** 最も Vs が低いのは後背湿地・泥炭質土だが、
これらは高塑性・低透水で**吸い出されにくい**。一方、吸出しの本命である旧河道の砂・
埋戻し砂は Vs が**それより高い**。すなわち `-AVS30` は、最重要リスク単元を
リスクの低い泥炭・粘性土より**下位に並べる**。

陥没 susceptibility は軟らかさに対して**単峰**（緩い非粘着性砂でピーク）であり、
単調写像では表現できない。これは重みの調整では直らない、写像の形の問題である。

さらに2点。**深度スケールが1桁ずれている**（下水道本管の埋設深は概ね1〜5m、
取付管は0.5〜2m。AVS30 は0〜30mの走時平均で、実質は沖積層厚を測っている）。
**地下水位が入っていない**（ゼロメートル地帯では GL-1〜3m にあり、
管内流入が吸出しの主要駆動力になる）。

## 4-1. 代替指標も検討したが、入手形態が条件を満たさなかった

機序的により適切な代替として、国土地理院の**明治期の低湿地データ**を二値フラグとして
使う案を検討した。「緩い埋土＋高地下水位」という機序の中核に直結し、二値なので
人手で割り当てる数値がゼロで、標高も含まない。

しかし提供形態は**ラスタタイル**（`lcmfc2`）であり、AOI上のタイルを取得して解析したところ、
**256×256ピクセルに12,533色**あった。基図・道路・注記を焼き込んだレンダリング済み地図画像で
あり、低湿地の判定には「どの色を低湿地とみなすか」を人手で決める必要がある。
それでは AVS30 を退けた理由と同じ欠陥を抱えることになる。

ベクタ形式での提供を追う道は残っているが、本件はここで打ち切った。

# §5 なぜ「測らない」を選んだか

ρ を下げること自体は容易であり（乱数でも下がる）、下げた結果を公表すれば
「独立性を改善した」と語ることはできた。**しかしそれは検証ではなく、検証の外形である。**

本プロジェクトは `docs/SPEC.md` §5 で「何を主張でき／できないかを厳密に示し、それを機械で
強制・再現すること」を核に置いている。情報量のない実験を実施して数値を更新することは、
その規範に反する。

したがって測定を実施せず、**この設計では意味のある検証にならないと分かった事実**を
成果として記録する。

## 5-1. 次に測るなら、最低限これが必要

本件で得られた要件を、将来の再挑戦のために残す。

1. **陰性対照アーム**。susceptibility を空間シャッフルした場（周辺分布は保存、空間構造だけ破壊）
   および乱数場で ρ を算出し、実データがそれらを有意に下回ることを示す。これがなければ
   ρ の低下は何の証拠にもならない
2. **重み変更のみのアーム**。第4項を入れず重みだけ変えた条件を測り、
   「新情報の寄与」と「重み配分の算術効果」を分離する
3. **ρ の算出式の凍結**。対象列・対象集合・tier化前であることを擬似コードで固定する
4. **4項すべての前処理と `_normalize` 実装の凍結**。`eligible_pool`・tier分位数・格納型も含む
5. **判定閾値と撤回規則**。どの値なら「変化なし」と呼ぶか、その場合に項を外すのかを先に決める
6. **指標は機序から選ぶ**。侵食性・地下水位・埋設深に結びつく量を、
   方法論上の都合で機序的に不適切な量に置き換えない

## 5-2. ただし、本質的な制約はデータアクセスである

上記をすべて満たしても、**本プロジェクトの根本的な制約は解けない**。

現在の管路データは合成であり（`SyntheticPipe`、Illustrative表示）、布設年・管種・口径・
埋設深という劣化を左右する情報が一つも入っていない。**入っていない情報は、どんな手法でも
当てられない。** 商用化ロードマップが「管路データ」の難度を「高」とし、その理由を技術ではなく
「データ提供元との調整」としているのは、この意味である。

地盤情報の追加は、その制約を迂回できるかの試みだった。本件はその迂回が
（少なくともこの指標と設計では）成立しないことを示した。
